# Using Github to manage your code

## What is version control and why use it?

Version control is a method of organizing and keeping track of file changes in a project. Github is a software versioning and revision control system that the Pugh Lab uses to manage code and other documents. Save code to the Git repository, but make sure to save data files to the cluster (H4H/Mordor, as they are often large files).

There are many reasons why using version control is important. First of all, using version control means that there is a history of all changes made and a back-up so that one can revert to previous versions to correct mistakes, as well as keep track of the progress of the project. Secondly, version control aids in collaboration. When working with many people on a project, all can track each other’s edits and decide how changes are merged.

Finally, Git is a key tool for ensuring reproducibility of results. We can save the version that is included in an article, so that the code, the graphs and diagrams, the draft is the same as the one submitted. Using version control prevents fraud, as the information about the history of the changes is so closely attached to the files.

Before using version control, one’s folders may be littered with files of the form Thesis\_1, Thesis\_ 2, Thesis\_old\_version, Thesis\_old\_old\_version. Version control is one more useful tool in keeping track of code (“What did that script do again? Which one is the newest version of that draft?”). Committing small changes, even when working on a sole-responsibility project is very useful in keeping track of the progress of the project. Doing this aids in goal setting and improving productivity (“I will try to fix this loop of the function, then commit the new version”).
