## Additional Details

### **\~/pughlab/bin**

* Where external software (scripts, source code, binaries) should be stored and installed (if possible).
* When searching for software start with `module avail` then look in `$~/pughlab/bin` and for custom script written by pugh-lab members see `~/pughlab/src`

### **\~/pughlab/data**

* For data generated specifically for a pugh-lab project. Usually this has been produced at PMGC, OICR and possibly SickKids.

**Space Saving Notes:**

* All fastqs produced by PMGC are started permanently on their servers so once these have been converted to bams/expression matrices, etc. etc. they can be deleted with no fear of loss of data.
* Sometimes we receive or generate redundant alignment files that are easily inter-convertible and contain essentially the same information so only one of these \*usually\* needs to be retained for downstream analysis. These may include .sam files that are converted to .bams, bwa (pre-processed bams) that have been co-cleaned and dup marked etc. (processed bams).

### **\~/pughlab/external\_data**

* For externally generated data. This may be public data (ex. TCGA, TARGET) or data generated by collaborators.

### **\~/pughlab/projects**

* Where most of your project-specific scripts, working data and final results will reside.
* Many of us have found that the following directory structure is a good way to organize most genomics projects:

```
 ~/pughlab/projects/PROJECT_NAME
 │   └── DataType1 (ex. Exome)
 │       ├── data_links
 │       ├── scripts
 │       ├── Tool1
 │       ├── Tool2
 │       └── Tool3
 │   └── DataType2 (ex. RNA-Seq)
 │       ├── data_links
 │       ├── scripts
 │       ├── Tool1
 │       ├── Tool2
 │       └── Tool3
 
```

* Some examples can be found here:
  * `/cluster/projects/pughlab/projects/NPC/HK_WGS`
  * `/mnt/work1/users/pughlab/projects/HNSCC_Engraftment`
* Each project will of course have it's own nuance but this structures is a good place to start.

**Space Saving Note:**

* Sym-links are your friend. They allow you to keep only one copy of each files but have it “appear” in an unlimited number of locations. This is particularly useful if results/input is used/processed by multiple tools, or if you run many iterations of the same analysis and choose a \*winner\* but wish to keep the other versions.

### **\~/pughlab/references**

* For genome fastas, annotations, intervals that generally aid informatics tools in the analysis and interpretation of genomics data.
* One important subfolder is `~/pughlab/references/intervals` which houses bed files for various panels (ex. SureSelect Exomes)

### **\~/pughlab/src**

* For custom scripts written by pugh-lab members and collaborators.
* Rule of thumb: If you or someone else could conceivably use a script/function/tool that you have written again, go ahead and put it in src. The more resources that are stored here for easy access and discovery by others in the group the better!
